# polyvote

> もともと Polymarket を試してみるつもりでしたが、残念ながら VPS のレイテンシ問題がどうしても解決できなかったようです。機会があれば、またプロジェクトを再開するつもりです。

**ステータス：一時停止中（2026-10-13）**。すべてのサービスを停止し、デプロイ先の VPS もシャットダウン済みです。最初から最後まで**シャドー（模擬取引）**のみで運用しており、ウォレットの秘密鍵を読み込んだことも、実際に発注したことも一度もありません。

---

## 概要

polyvote は、予測市場 [Polymarket](https://polymarket.com) で自動売買を試す実験プロジェクトです。2 つのフェーズがあります。

### フェーズ 1：スロー市場、複数モデルによる投票（終了）

選挙・スポーツ・ニュースなどの通常のイベント市場を対象に、複数の LLM に確率を「合議」させます。

```
Haiku が一度だけ調査  →  3 モデルが独立に見積もり  →  決定モデルが判断  →  コード側のハードなリスク制限  →  発注
  (Web 検索はここだけ)    Claude Opus     ┐
                          Claude Fable    ├─ 市場価格は見せない・ツールなし
                          GPT (codex)     ┘
```

- 投票モデルには**価格を見せません**。市場価格をそのまま繰り返すだけにならないようにするためです。
- キャリブレーションのルールは [valory-xyz/mech-predict](https://github.com/valory-xyz/mech-predict) の superforecaster プロンプトを参考にしています。
- LLM API は使わず、`claude` / `codex` CLI を使い捨てのサブプロセスとして起動し、サブスクリプション枠で動かします。
- `risk.py` がハードゲートです。モデルが何と言っても上書きできず、1 つでも条件を満たさなければ注文全体を拒否します。

2026-07-22 に終了し、高速市場に移行しました。設計の詳細と失敗談は [docs/slow-market-design.zh-CN.md](docs/slow-market-design.zh-CN.md)（中国語）にあります。

### フェーズ 2：高速市場 Fast V2（本体）

Polymarket の **5 分間の暗号資産 Up/Down 市場**（BTC・ETH・SOL・XRP）が対象です。資産ごとに独立したイベント駆動型エンジンが動きます。

```
RTDS Chainlink / Binance 価格 ─┐
                              ├─> タイムスタンプ検証 ─> シグナルモデル ─> ハードゲート
CLOB WebSocket ─> ローカル板 ──┘                                          │
                                                                         ├─> SQLite に注文意図を記録 + 資金を拘束
                                                                         ├─> 実測レイテンシ後の板を再現
                                                                         ├─> 板を 1 段ずつ FAK 約定（約定 / 一部約定 / 拒否）
                                                                         └─> 公式の決済結果と照合
```

- **ローカル板**：フルスナップショットと差分更新で管理します。古いイベント、クロスした板、同期ずれは拒否します。
- **資金台帳**：SQLite（WAL）。注文意図の時点で資金を拘束し、実際に約定して初めてポジションを作ります。決済は冪等なトランザクションで、再起動しても台帳はリセットされません。
- **レイテンシの分解**：判断計算、HTTP 往復、イベントループの待ち時間、プラットフォームの `seconds_delay` を別々に記録し、すべて P95 で報告します。一番良かった 1 回の値は使いません。
- **実験設計**：チャンピオン戦略、正規化した $5 注文でサンプルを集め続けるオブザーバー、パラメータを固定したホールドアウト挑戦者で構成しています。自動レビューは変更の提案しかできず、稼働中の戦略を書き換えることも、実弾取引に切り替えることもできません。
- **ダッシュボード**：`fast_dashboard.html` で口座、注文のライフサイクル、レイテンシの内訳、レビュー結果を表示します。データが 2 秒以上古くなると全画面で警告します。

稼働環境は Polymarket の CLOB に近い AWS Lightsail ダブリン（月 $5、2 vCPU、512 MB）です。

## 結果と結論

2026-08-01 時点、最後の完全な集計です。

| 指標 | 結果 |
|---|---|
| オブザーバーの模擬取引（公式決済済み） | 8,713 件 |
| 手数料・スリッページ・レイテンシ控除後の純損益 | **−$2,097**（ROI −5.1%） |
| 1 件あたり損益の 95% 信頼区間 | [−$0.32, −$0.16]（区間全体がマイナス） |
| 平均予測確率 vs 実際の勝率 | 70.9% vs 59.4%（約 11.5 pt の過信） |
| 制御可能経路のレイテンシ P95（目標 < 100 ms） | 最後の完全計測で 383–385 ms。同じプロセスでも 83 ms から 848 ms の間で大きく変動 |
| チャンピオン台帳（資金上限あり） | $30.00 → $7.79、リスクゲートにより永久ロック |
| ホールドアウト挑戦者 2 本 | どちらも自身の損失ゲートで停止 |

**レイテンシ**：コード側で疑える点はほぼ潰しました（スレッドプールの待ち、IPv4/IPv6、書き込みの増幅、コネクションの劣化など）。残ったのは主に $5 の共有ホストのスケジューリングの問題で、ホストの CPU steal は常に 50–84% に達していました。静かな時間帯には約 83 ms まで下がるので目標自体は達成可能ですが、安定して達成することはできませんでした。

**もう半分の問題**：振り返りでは、シグナルが勝率を系統的に過信していたこともわかりました。戦略が見ていた 4 pt のエッジは、約 11.5 pt のキャリブレーション誤差より小さかったのです。再開するなら、レイテンシの安定したホストに加えて、確率キャリブレーションの作り直しも必要です。

2026-08-15 にサービスを停止し、2026-10-13 に VPS をシャットダウンしました。

## ディレクトリ構成

| パス | 内容 |
|---|---|
| `fastbot.py` | 単一資産の高速市場エンジン：イベント駆動の判断、次の市場の事前準備、レイテンシ付き模擬約定、公式決済 |
| `fastmulti.py` | 4 資産のエンジンを 1 つのポートフォリオとしてまとめて監視・実行 |
| `fastchallenger.py` | パラメータを固定したホールドアウト挑戦者 |
| `fastdash_server.py`、`fast_dashboard.html` | 高速市場ダッシュボード |
| `polyvote/fast*.py` | 板、シグナル戦略、資金台帳、オブザーバー、レビュー、状態書き込み |
| `fast_*.yaml` | ポートフォリオと挑戦者の設定 |
| `run.py`、`dashboard.py`、`polyvote/{brain,desk,risk,…}.py` | フェーズ 1 のスロー市場（終了） |
| `deploy/` | systemd ユーザーユニット、デプロイスクリプト、SSH トンネルスクリプト |
| `tests/` | ユニットテスト |

## 動かし方

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-fast.txt -r requirements.txt pytest
.venv/bin/python -m pytest tests -q

# 高速市場（シャドー）
.venv/bin/python fastmulti.py --portfolio fast_portfolio.yaml
.venv/bin/python fastdash_server.py --host 127.0.0.1 --port 8920 --state-dir .
```

高速市場のコードには実弾で発注する経路がありません（終了したスロー市場の `execute.py` にはあり、`dry_run: false` と環境変数の秘密鍵が両方そろった場合のみ有効になります）。ダッシュボードには認証がないため、`127.0.0.1` だけで待ち受け、外部からは SSH トンネル経由で見てください。サーバーへのデプロイは `deploy/` のユニットファイルを参照してください。
